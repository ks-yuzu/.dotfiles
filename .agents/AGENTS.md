
デフォルトルールを記載する。リポジトリ側の指定と競合する場合はそちらを優先する。

## ドキュメンテーション
- ドキュメントは docs/ 内に配置する
- 実装中に仕様変更・追加があった時は、必要に応じて `docs/spec.md` に追記する

## 作業フロー
- worktree を切る。origin/main が先行していることがあるので注意
- main ブランチに直接 commit せず、PR を作成する
- 作業が完了したら、/code-review でレビューを行う
- 改善まで完了した後、納品を行う
- 受領完了後に、PR のマージ・main ブランチの pull を実施する

## (主に codex 向け) エージェントの分担
- メインエージェントが設計判断、進捗管理、統合、最終的な品質確認を担当する
- 独立して完結する単純な実装、テスト追加、レビューは Terra / Luna などのサブエージェントへ移譲してよい
- 同じファイルを複数エージェントが同時に編集しない。メインエージェントは差分を確認し、統合後にテストや検証を行う
